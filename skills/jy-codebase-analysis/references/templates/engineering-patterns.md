# Template: Engineering Patterns & Standards (`04-engineering-patterns.md`)

**Audience:** architects and developers who need to understand, and then
follow, the codebase's structure.

**Source:** verified pattern claims (P-…), "Considered, not found" entries,
and the "Conventions" and "Anomalies" sections of every card.

**Voice:** descriptive first ("what this codebase does"), then derived
guidance ("to fit in, new code should…"). Standards here are the **observed**
ones, not an ideal. Where the code is inconsistent, report the split with
rough proportions and examples of each side.
